# Partner audit and integration log (2026-10-31)

The requirements below come from the official HF26 challenge hub (https://dev.to/challenges/hf26) and the Week 4
challenge page, both read on 2026-10-31. The budget is ₹0, so nothing below needed a payment method, a trial or a
credit card.

## Audit: all 20 Week 4 prize categories

| Category | What the hub asks for | Decision | Why |
| --- | --- | --- | --- |
| Gemma (featured) | Use Gemma in the project | **Kept** (existing) | Every agent role runs on Gemma 4 E4B locally. |
| Mastra | Orchestrate an agent over open models / memory and tools / a workflow that triages GitHub issues | **Kept** (existing), extended | Lead Engineer agent and the upstream-issue triage workflow. Its Lead can now search the restoration memory (see Tiger Data). |
| Sentry Agent Tracing | Show the agent's work (setup, latency, tokens, cost), what you found and debugged, with traces or screenshots | **Kept** (existing) | Engine and companion traces with no prompts or code. |
| SerpApi | Live web search for an agent / ground RAG / track news | **Kept** (existing) | Hunter web discovery and the cited research job. |
| GitHub Copilot | Copilot coding agent, CLI or app; *"automate your project with GitHub Actions"*; review PRs with Copilot | **Added: GitHub Actions** | CI runs clippy, the Rust and Mastra tests, and the signature replay end to end in Docker on a clean runner, then uploads the Inheritance Record. The claim is made only on the hub's GitHub Actions wording. Copilot itself was not used to build the project. |
| Temporal | Make the agent durable: a Temporal workflow that survives failures, retries flaky tool calls and resumes | **Added** | `companion/temporal`: one durable workflow over the engine's jobs. It was demonstrated live with a worker crash in the middle of a job. |
| Tiger Data | Store embeddings with pgvector and run hybrid keyword + vector search for an agent; Tiger MCP | **Added (self-hosted)** | Restoration memory: Tiger Data's open-source Postgres image with pgvector and pgvectorscale (DiskANN), hybrid search exposed to the Lead agent. It runs locally, not on Tiger Cloud, because repair text can quote inherited source. |
| Browserbase | Drive a live site with Stagehand / pull context for an open model / repeatable workflow | Not added | The only site the engine would browse is a project's static docs, which plain fetching already covers. Stagehand would need its own model loop on a 4B model. That is real work with little gain, and it couldn't be verified in time. |
| ElevenLabs | Voice for an agent / transcribe audio / narrate the demo | Not added (possible) | The only honest fit is narrating the demo video. That needs your ElevenLabs API key in `.env` and fits the free tier. It's a demo improvement, not a product change. |
| Entire | Share agent sessions in the write-up / search past agent work | Not added | Sharing the build sessions conflicts with the standing rule not to upload the agent-session transcript. |
| Auth0 for AI Agents | Sign-in for agents, Token Vault, human approval, fine-grained RAG authorisation | Not added | Single-user local tool: every action already needs a person's click. Adding an Auth0 tenant would add a cloud dependency without protecting anything new. |
| MongoDB Atlas | Atlas as the data layer / vector search / agent memory | Not added | Would duplicate the restoration memory. Two vector stores would be the kind of superficial integration we're avoiding. |
| Backboard | R-CLI, compare models via one API key, memory/RAG for an OSS assistant | Not added | Hosted memory and RAG would send repository text off the machine (conflicts with `local_only`), and would duplicate Tiger Data. |
| Ultramarine (Paper Instruments) | Use the hosted model for research or document reasoning; report cost | Not added | Hosted model. Repository content can't go to it under `local_only`, and the $5 credit has to be claimed by you. |
| Render (featured) | AI runtime, host an agent's front end, or run Hermes/OpenClaw | Not added | The engine needs local Docker and a local model, and a hosted front end with no engine behind it does nothing. |
| DigitalOcean (featured) | Build or deploy on DigitalOcean | Not added | Needs a payment method on the account (₹0 rule), and the same local-first problem as Render. |
| TabPFN (featured) | Tabular prediction from historical data | Not added | There's no honest tabular dataset: four inheritances can't train or validate a predictor. |
| Tinker (featured) | Fine-tune a model and show improvement over a baseline | Not added | A fine-tune and a fair evaluation can't be done and verified before the deadline. |
| Arduino (featured) | Build with an Arduino UNO Q | Not added | No hardware involved. |
| .tech domain | Put the project live on a claimed .tech domain | Not added | Nothing meaningful to host live (the product is local). The free first year renews at $29.99, which is a billing risk. |
